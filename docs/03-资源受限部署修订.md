# 模板宝 资源受限部署修订（v1.1）

> 约束条件（来自你的实际情况）：
> - 个人开发者，**没有 CDN / OSS 预算**，所有内容放在服务器上
> - 模板源文件上传到网盘后，**服务器上的原生文件必须删除**
> - 服务器规格：**2 核 / 2G 内存 / 40G 硬盘**
>
> 本文回答：这些约束下方案有没有问题、怎么改、现在能不能开工。

---

## 0. 结论

**可以开发，但有 5 处必须调整，且 1 个未知项（带宽）需要你确认。**

| 约束 | 判断 | 调整 |
| --- | --- | --- |
| 无 CDN/OSS | 可接受（低流量阶段） | 图片规格再压缩、Nginx 强缓存、带宽成为并发天花板 |
| 2G 内存 | 可跑，但需瘦身 | **去掉 Redis**、MySQL 低配、2G swap、单 Node 进程、禁止在服务器构建 |
| 40G 硬盘 | 够用 | 图片约 0.5–2.8G（1000–5000 模板）；源文件临时目录 8G 配额；校验后即删 |
| 源文件删除 | 可行，但有前提 | **先校验网盘、再删除**；保留审计；删除后不可重渲染（本地留底） |
| 无 CDN 带宽 | **唯一未知** | 需确认服务器带宽；3–5Mbps 可支撑早期小流量 |

**因此：不是"没有问题"，而是"问题都能用不花钱的方式解决"。我按本文修订后的规格开工。**

## 1. 内存预算（2G 怎么活下来）

| 组件 | 预估内存 | 措施 |
| --- | --- | --- |
| 系统 + 宝塔面板 | 250–350 MB | 关闭不用的面板插件 |
| Nginx | 30–50 MB | 仅静态 + 反代 |
| MySQL 8 | 350–450 MB | `innodb_buffer_pool_size=128M`、`performance_schema=OFF`、`max_connections=40` |
| Node API + Worker | 250–350 MB | **单进程**，API 与任务轮询放一起；`--max-old-space-size=384` |
| PM2 | ~30 MB | 单实例，`max_memory_restart=500M` |
| 网盘 CLI（bdpan / 夸克 skill） | 瞬时 50–100 MB | 串行执行，同一时间只跑 1 个同步任务 |
| **合计** | **约 1.0–1.3 GB** | 再配 **2G swap** 兜底 |

**关键调整：一期不用 Redis。**
- 任务队列直接用 MySQL `Task` 表 + 每 10 秒轮询的 worker（wallpaper-manager 的 WallMuse 就是这样做的）；
- 省掉 Redis 进程 + 运维风险（wallpaper-manager 文档专门警告过 Redis 共用 FLUSHALL 的问题）；
- 以后量大了再加 Redis，接口不变。

## 2. 磁盘预算（40G 怎么分）

| 用途 | 预估 | 说明 |
| --- | --- | --- |
| 系统 + 宝塔 + MySQL + 运行时 | 12–15 GB | 装完 LNMP + Node 后 |
| 封面 / 缩略图 / 预览图 | 0.5–2.8 GB | 约 550KB/模板 × 1000–5000 |
| 源文件临时区 `storage/private/incoming` | **≤ 8 GB（硬配额）** | 同步成功即删；超配额暂停接收新上传 |
| 数据库 / 日志 / 备份 | 2–3 GB | MySQL 数据很小；日志轮转；备份压缩 |
| **峰值合计** | **约 25–28 GB** | 40G 留 12G+ 余量 |

**清理任务（必须实现）：**
1. 每条源文件记录 `uploadedAt / syncedAt / sourceCleanedAt`；
2. 网盘同步成功并**校验远端文件大小一致**后，立即删除源文件；
3. 失败保留重试 3 次；超过 24h 未成功的源文件强制清理并告警；
4. 每 30 分钟扫描一次 incoming 目录；磁盘剩余 < 8G 时暂停接收上传。

## 3. 图片规格（无 CDN 版，比 v1 更小）

| 图 | 尺寸 | 目标体积 | 数量 |
| --- | --- | --- | --- |
| thumb 缩略图 | 360×480（3:4） | ≤ 30 KB | 1 |
| cover 封面 | 800×1067（3:4） | ≤ 120 KB | 1 |
| preview 预览页 | 宽 800 | ≤ 80 KB | 4 |
| **单模板合计** | — | **约 450–550 KB** | |

- 1000 模板 ≈ **500MB**；5000 模板 ≈ **2.5GB**。
- 首屏列表 10 张缩略图 ≈ 300KB（3Mbps 下约 0.8 秒可接受）。
- 详情页约 440KB（3Mbps 下约 1.2 秒）。
- **不再单独生成 AI 输入图**：服务端直接把 cover + 3 张 preview 的 base64 发给 DeepSeek，省磁盘、省一次转换。
- 小程序 `<image>` 必须加 `webp="{{true}}"`（微信默认不解析 WebP 网络图）。
- 文件名带内容 hash，Nginx 设置 `Cache-Control: public, max-age=31536000, immutable`。

**Nginx 关键配置：**

```nginx
http {
  sendfile on;
  tcp_nopush on;
  open_file_cache max=2000 inactive=60s;
  gzip on;
  gzip_types text/plain application/json application/javascript text/css;
}
location /assets/ {
  expires 1y;
  add_header Cache-Control "public, immutable";
  access_log off;
}
```

## 4. 源文件生命周期（"上传网盘后删除"的正确做法）

```
① 桌面 CLI 分片上传源文件
      → storage/private/incoming/<batchId>/<sourceHash>.<ext>
② 服务端入队 netdisk_sync（串行，同一时间只跑 1 个）
③ 百度/夸克 CLI 上传 → 创建永久分享
④ 校验：远端文件存在 + 大小一致 + 分享链接可访问
⑤ 写 NetdiskLink / ShortLink → 标记 sourceCleanedAt → 删除本地源文件 → 审计日志
⑥ 管理端显示「已上云 · 源文件已清理」
```

**失败保护：**
- 上传/分享/校验任一步失败 → **不删**，保留重试；
- 重试 3 次仍失败 → 保留 24h 供排查，之后清理并告警；
- 删除是本地 `unlink`，不影响网盘（夸克 CLI 没有删除命令，网盘文件只能手动清理）。

**代价（必须知道）：**
- 源文件删除后，服务端**无法重新渲染/重新分享**；如需重来，从桌面本地 dist 重新上传；
- 所以桌面端 `dist/` 和原始模板目录**必须保留**，不能删。

## 5. 取消"双交付"（小程序内直接打开文件）

复核文档里建议的"小程序内直接打开/转发"在 2C2G/40G/无带宽预算下**不成立**：
- 源文件不长期落盘 → 没有文件可直开；
- 大文件直下会吃掉服务器带宽。

**一期交付方式锁定：网盘短链 + 提取码 + 一键复制。** 后续若带宽/存储升级，再评估直开。

---

## 6. 构建与部署（2C2G 不能在服务器上构建）

Vite/Nest 构建峰值内存 > 1G，2G 服务器上构建容易 OOM 且拖慢线上服务。

| 环节 | 做法 |
| --- | --- |
| 构建 | **本机或 GitHub Actions** 构建 `apps/api/dist`、`apps/admin/dist`、`prisma` 产物 |
| 部署 | rsync 构建产物 + 源码；服务器只跑 `prisma migrate deploy` 和 `node dist/main.js` |
| 依赖 | 服务器装生产依赖（`npm ci --omit=dev`），不装 devDependencies |
| 进程 | PM2 单实例，`max_memory_restart: 500M` |
| 静态 | 管理端由 Nginx 托管；API 走 Nginx 反代 |
| 证书 | 宝塔免费 Let's Encrypt 证书（HTTPS 必须） |
| 替换策略 | 发布时先 `pm2 reload`，失败自动回滚上一版 dist |

## 7. 带宽：唯一需要你确认的数字

| 带宽 | 理论下载速度 | 单用户详情页（440KB） | 同时在线体验 |
| --- | --- | --- | --- |
| 1 Mbps | 125 KB/s | ~3.5 秒 | 1–2 人 |
| 3 Mbps | 375 KB/s | ~1.2 秒 | 3–5 人 |
| 5 Mbps | 625 KB/s | ~0.7 秒 | 5–8 人 |
| 10 Mbps | 1.25 MB/s | ~0.35 秒 | 10+ 人 |

**早期个人项目按 3–5Mbps 设计即可。** 如果只有 1Mbps，小程序能用但会慢，等有流量再升级带宽（通常比接 CDN 更简单）。

后期流量上来后的顺序：**先升级带宽 → 再考虑免费额度对象存储（七牛 10GB/月、又拍云联盟、云厂商新用户试用）→ 最后才上付费 CDN**。现在不花这笔钱是对的。

## 8. 共享服务器风险（需要确认）

如果这台 2C2G 还跑着 wallpaper-manager：

- **不要新装 MySQL/Redis**：直接复用现有 MySQL，新建 `templio` 数据库；
- 两个 Node 进程 + MySQL + 宝塔 ≈ 1.5GB，2G 会吃紧，需要看 `free -m` 实际占用；
- 建议最低 2C4G；如果暂时不加配置，就把两个项目错峰跑（同步/批量任务放夜间）。

如果是全新独立的 2C2G 服务器：按 §1 预算安装配置即可。
