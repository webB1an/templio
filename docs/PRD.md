## 1. 产品定位

「万用模板」是综合型模板资源库。用户按格式、使用场景、行业/人群和主题查找资源，查看预览、收藏、分享，并按当前运营模式免费获取或使用积分解锁资源。

管理端负责资源上传、网盘关联、AI 辅助分类、人工审核、发布、价格配置、积分规则、充值商品映射、订单核查与系统开关。

**商业模式**：前期所有资源免费开放，积累用户；后期开启积分模式，部分资源（如精品 PPT）按积分解锁，用户通过虚拟支付充值积分获取；同时网盘分享页的转存/拉新收益作为补充收入。

目标：所有功能在同一版本内建成；默认运行免费模式（`monetizationEnabled=false`）；完成平台资质和支付验收后，可由后台启用积分/虚拟支付，无需重写前端业务。

## 2. 核心产品原则

1. **完整实现，开关控制运营状态。** 不是把付费功能留待二期开发，而是开发积分、签到、充值、订单、兑换、后台配置等完整功能。初始配置 `monetizationEnabled=false`、`virtualPayEnabled=false`。
2. **免费模式不等于无条件公开全部记录。** 仅对"已发布、未下架、未被版权投诉/风控封禁"的资源免费展示链接。草稿、待审核、驳回、下架、封禁资源仍不可公开。
3. **AI 只提供辅助，不自动替代人工发布审核。** AI 基于封面/预览图与文件元信息生成标题、摘要、两级分类候选、标签和**建议积分价格**；默认进入待审核队列，不直接公开。
4. **模板价格和充值 SKU 分开。** 模板使用"积分价格"；虚拟支付平台商品是"购买积分包"。每个积分包的平台商品 ID 与价格必须与微信后台已发布的道具一致。
5. **余额与交易历史不可因关闭功能而被清空。** 关闭付费模式只影响当前可用业务，不删除积分余额、订单、积分流水或已解锁记录。
6. **免责声明不能替代授权。** 首批资源以**自制**为主，上传时仍需记录资源来源和授权声明；人工审核、投诉受理和快速下架均需实现。

## 3. 产品结构

### 3.1 小程序 Tabbar

- 首页
- 分类
- 积分（余额、签到、充值、明细聚合页）
- 我的

（签到不单独占 Tab，作为积分页内的一个区块呈现。）

### 3.2 首页

- 顶部品牌区与搜索入口。
- 搜索框：支持模板标题、摘要、关键词和标签检索；支持搜索历史、热门关键词和空结果推荐。
  - **搜索历史**仅存于小程序本地 Storage（最近 20 条，用户可清空），不上传服务端。
  - **热门关键词** = 后台配置的推荐词 + 近 7 天真实搜索词聚合 TopN（匿名统计）；冷启动期（无搜索数据）仅展示后台配置词。
- 公告条：后台可发布系统公告（标题 + 内容 + 生效时间），首页顶部展示，点击查看详情。
- 主视觉 Banner：后台维护图片、跳转类型、目标 ID、排序、开始/结束时间和启用状态。
- 快捷分类入口：PPT、Excel、Word、教学课件、节日模板、手抄报、合同模板、行业模板、幼师模板等。
- 内容区：最新上架、热门模板、精选模板、免费专区、按主题推荐。
- 模板卡片显示封面、标题、格式、关键标签、热度/收藏数（按产品配置选择）、免费/积分价格状态。
- 首页模块可由后台排序、开关、修改标题和配置每模块展示数量；不要求动态搭建任意复杂页面。

### 3.3 分类与列表

分类不只使用单棵树，采用多维分类：

- **格式类型**：PPT、Excel、Word、PDF、图片、压缩包/其他。**不支持视频类模板资源**（若上传内容中附带视频文件，按"其他"处理，仅展示通用封面，不转存、不截帧）。
- **使用场景**：工作总结、毕业答辩、述职报告、简历求职、教学备课、班会活动、手抄报、合同协议等。
- **行业/人群**：通用办公、教育、幼教、财务、人事、营销、学生等。
- **主题标签**：春节、中秋、毕业季、开学季、年会、年度总结等。

同一模板可关联多个维度节点与多个标签。分类页展示一级分类；进入后可切换一级分类/子分类，保留当前筛选条件。

列表支持：关键词、格式、场景、行业/人群、主题、免费/付费状态（仅积分模式）、排序、分页或触底加载、空状态、加载失败和重试。

**排序口径定义**：

- **热度分**：`heatScore = viewCount × 1 + favoriteCount × 8 + shareOpenCount × 2`（权重为初始默认值，可由后台配置）。热度分由定时任务（每小时）预计算并落库，排序走索引，不在查询时实时聚合。
- **综合排序**：`综合分 = 归一化热度分 × 0.7 + 新鲜度分 × 0.3`（新鲜度按发布时间指数衰减）。同样预计算。
- **最新**：按发布时间倒序。**热门**：按 heatScore 倒序。

分类初始数据由项目提供种子数据，后台可新增、编辑、排序、隐藏、调整父子关系。删除被使用的分类时禁止硬删除，需先迁移资源或改为禁用。

### 3.4 模板详情

展示：

- 封面与预览图；多页/多文件资源可横向或纵向浏览预览。
- 标题、摘要、格式、文件大小（可为空）、页数（可为空）、标签、更新时间、使用场景。
- 当前获取方式：免费模式、免费模板、积分解锁模板。
- 收藏、分享、举报/版权投诉入口（统一进入投诉流程，投诉类型区分侵权/违规/其他）。
- 资源说明、使用提示、版权声明/免责声明。
- 获取资源按钮与网盘分享链接展示/复制；复制前通过服务端权限逻辑确认是否可获取。（分享链接自带提取码，系统不单独维护提取码字段。）

**免费模式**：所有已发布且正常可用的模板有效价格为 0，详情页可直接展示网盘链接；不扣积分、不要求充值。建议使用"查看/复制资源链接"交互，避免页面载入时将全部链接暴露在列表接口里。

**积分模式**：免费模板直接查看链接；付费模板显示所需积分。用户未解锁时只返回预览和价格；扣分成功后创建永久解锁记录并返回链接。解锁记录默认永久有效，即使后续调整模板价格，已解锁用户不再次扣分。

分享卡片只包含标题、封面和小程序详情路径，不得把网盘链接或付费模板敏感字段写入分享内容。

### 3.5 收藏、历史与分享

- 收藏/取消收藏；收藏列表。
- 最近浏览记录：每用户保留最近 200 条且不超过 90 天，超出的由定时任务清理；支持用户手动清空。
- 分享到好友/群聊；通过分享进入详情页。
- **分享奖励**：其他用户通过分享卡片进入详情页并完成有效浏览（停留详情页 ≥ 5 秒）时，分享者获得积分奖励；奖励数额由后台配置（`shareRewardCredits`）。
  - 防刷规则（服务端强制，不接受客户端上报）：① 同一分享者对同一模板仅首次有效打开计奖；② 每用户每日分享奖励上限（`shareRewardDailyLimit`，后台可配，默认 10 次）；③ 接收者必须是平台登记的有效用户且与分享者非同一 openid；④ 全部写入积分流水，带幂等键。
- 分享打开量（`shareOpenCount`）同时计入热度分口径。

### 3.6 积分页与充值

积分页聚合展示：当前余额、签到区块（见 3.7）、积分获取/消耗说明、充值档位、订单入口、积分明细。

积分包由自己的管理后台维护，包括：业务 Key、用户显示名称、商品描述、微信平台道具 ID、平台价格（分）、赠送积分、额外赠送积分、总发放积分、启用状态、排序、活动角标文案（`badgeText`）与活动说明（`activityNote`）。

**充值档位需要双端配置，不能只改自己的后台：**

1. 微信公众平台后台：进入"虚拟支付 → 道具管理"，创建并发布每一个虚拟支付道具，确认其 `productId` 和价格。
2. 万用模板管理后台：增加对应的充值商品，录入完全一致的微信道具 ID 和价格，再配置该档位发放多少积分、赠送多少积分、是否启用与排序。
3. 后端创建订单时只相信服务端保存的 SKU 配置，前端只能提交 SKU Key，不能提交应付价格、积分数量或微信道具 ID。
4. 如果微信道具 ID/价格与本地配置未核对，后台应标记为"待核验"，并禁止启用；由于平台商品状态通常不能由普通业务 API 完整自动校验，需由管理员勾选"已在微信后台创建并发布，ID/价格已核对"。
5. 改变价格时先处理微信平台道具，再更新本地映射；不能只在小程序显示一个新价格。老 SKU 可停用但不应删除订单历史。

说明：微信平台的"道具"应对应积分充值档位；每个模板的积分价格是在万用模板自己的数据库中配置，不需要为每一个模板单独创建一个微信虚拟支付商品。

### 3.7 签到（积分页内区块）

- 每个自然日最多签到一次，按服务器时区（默认 `Asia/Shanghai`）计算。
- 签到奖励与连续签到奖励可在后台配置；默认每日固定积分，暂不做概率抽奖。
- 后端通过 `(userId, date)` 唯一约束防重复领取；连续签到天数由服务端计算，不信任前端传值。
- 积分页展示今日签到状态、连续天数、最近签到日历、奖励规则与记录。
- 当积分模式关闭时，签到区块保留但明确显示"当前免费模式，签到不发放积分"；不累计可兑换积分。若以后重新启用积分模式，从重新启用后的签到开始发奖。

### 3.8 我的

- 微信登录用户信息（仅收集必要字段）。
- 积分余额、积分明细、充值订单、已解锁模板。
- 我的收藏、浏览记录。
- 意见反馈（结构化反馈表单，见数据模型 `Feedback`）。
- 用户协议、隐私政策、版权投诉、免责声明。
- 注销/删除账号相关入口及流程（按最终账号体系与法律要求实现）。

## 4. 后台功能范围

### 4.1 工作台

- 资源总数、待审核数量、已发布数量、下架数量。
- 上传任务和 AI 任务成功/失败数。
- 近 7/30 天浏览、收藏、解锁数据。
- 充值金额、订单状态、积分发放/消耗总量（只有开启付费后展示商业数据）。
- 失败任务重试入口；异常事件通过飞书群机器人实时告警（见 13）。

### 4.2 资源管理

- 单条录入、批量上传、批量关联网盘资源、批量编辑、批量上下架。
- 上传后资源默认 `draft/pending_review`，不能直接公开。
- 字段：标题、摘要、封面、预览图、格式、源文件名、文件大小、页数、网盘平台、网盘文件 ID、分享链接（自带提取码）、授权来源、权利人/授权说明、授权凭证备注、积分价格、分类、标签、状态、发布时间。
- 一条模板可包含多个关联文件（例如一个课件包包含 PPT、PDF、配套素材）。
- 网盘上传成功但 AI 失败时保留资源记录，可重试 AI；AI 成功但审核未过时只保留草稿。
- 链接健康检查：管理员可手动检查资源链接状态；如网盘 API 支持则加入定期检查和失效提醒。

### 4.3 AI 自动处理与分类

使用 DeepSeek API。`DEEPSEEK_API_KEY` 只配置在服务器环境变量中，不能下发到小程序或浏览器。模型名、提示词版本、超时、重试次数、置信阈值可以由服务器配置；API Key 不在普通设置表单中明文保存。

**AI 的输入**：封面图/预览图（图片识别）+ 源文件名、扩展名、大小等元信息。**AI 的职责**：生成候选标题、摘要、**两级分类**（一级分类 + 二级分类候选）、主题标签、关键词、建议积分价格和审核提示。不做全文内容提取，不做复杂场景判断。

处理工作流：

1. 接收本地上传/网盘上传/网盘链接录入。
2. 获取源文件元信息（名称、扩展名、大小、平台文件 ID）与封面/预览图。
3. 调用图片识别模型生成候选标题、摘要、分类、标签、建议积分价。
4. 后端校验 AI 返回 JSON Schema；字段不合法则重试或标记失败。
5. 依据置信度路由：高置信度也只进入待人工审核队列；低置信度额外标记"需要重点复核"。
6. 管理员修改、确认版权声明与资源链接，确认/调整积分价格（AI 建议价仅作候选，默认 0），审核通过后手动发布。

任务要求：任务状态可观察（queued/running/succeeded/failed/retry_waiting）、错误信息可查询、支持幂等重试、退避重试、同一资源不能重复生成多份有效任务。原始 AI 响应可按需保存用于排障，但注意控制个人数据和内容留存。

**图片识别实现要点**（官方文档 <https://api-docs.deepseek.com/zh-cn/guides/vision>）：

- 使用 `deepseek-flash` 模型（OpenAI 兼容 `chat/completions`，`base_url=https://api.deepseek.com`），`content` 为 block 数组，图片以 `image_url`（外部 URL 或 base64 data URL）传入。
- 支持格式 JPEG/PNG/GIF/WebP；单图 base64 ≤ 32 MiB；请求体 ≤ 48 MiB；单图 token 消耗上限 1024（超尺寸自动缩放）。
- 图片只能出现在 `user` 消息中；prompt（分类候选清单、输出 JSON Schema 约定）放在同条 user 消息的 text block 内。
- 上传管线生成的预览图为公开 URL（OSS/服务器静态资源）时优先传 URL；否则传缩略图 base64，控制请求体大小。

### 4.4 预览生成（截图方案）

**不使用服务端文档转换（无 LibreOffice）。** 预览素材全部由管理员在上传时提供：

- **封面图**：必填，列表卡片与分享卡片使用；建议 3:4 或 16:9 统一比例。
- **预览截图**：1–5 张，展示模板实际效果（首屏、内页、亮点页）；详情页横向浏览。
- 图片类资源：服务端仅做**缩略图生成**（轻量，sharp 库即可），原图保留在网盘侧。
- PDF：不做页面转图，仅展示封面/截图与元信息（文件大小等）。
- 压缩包/其他：通用封面 + 文件清单（若能安全解析）+ 资源链接；禁止服务端解压或执行内容。
- 上传时校验图片格式（JPEG/PNG/WebP）与大小（单张 ≤ 10MB），超限前端压缩后再传。
- AI 分类的输入即这些截图（`deepseek-flash` 图片识别），管线天然一致。

收益：服务器零转换负载（对 2C/1.6G 小机器至关重要）、预览效果 100% 可控、模块故障面大幅缩小。未来若模板量大、人工截图成本高，可在服务器升配后将 LibreOffice 转换作为可选增强模块加入，不改变现有数据模型（预览图字段本就是多张图片列表）。

### 4.5 分类/标签管理

- 多维分类树和标签词库。
- 手工编辑分类、别名、父子关系、顺序、状态。
- 批量将模板迁移到其他分类。
- AI 分类结果可同时返回多个维度与标签；发布前由管理员确认。
- 不能直接删除已关联分类；需迁移或禁用。

### 4.6 定价与积分规则

- 全局积分付费模式开关。
- 虚拟支付充值开关。
- 签到开关与奖励配置。
- 分享奖励开关、单次奖励积分、每日上限配置。
- 热度分权重配置（浏览/收藏/分享打开三项权重）。
- 积分包 SKU 配置。
- 模板积分价格：每条模板可配置非负整数积分；默认 0；AI 生成建议价供管理员参考。
- 首期不设置积分过期；若未来要加过期规则，必须先完善协议、通知和退款/投诉处理方案。
- 管理员手动增减积分必须填写原因，写入不可变积分流水；需支持对账，不允许直接改余额字段。

### 4.7 订单和积分流水

- 充值订单列表、订单详情、平台订单号、商户订单号、用户、SKU、下单金额、状态、通知次数、发放积分数量、退款/投诉状态。
- 积分流水：充值入账、赠送入账、签到、分享奖励、模板解锁扣减、管理员调整、退款/回收（如规则允许）。
- 订单与积分入账在数据库事务中完成；平台回调必须幂等；重复回调不得重复发积分。
- 对未收到回调的订单支持主动查单和补单；只允许后端查询并且校验订单所属用户。
- 不允许客户端回调成功就直接发积分；必须以服务端校验的支付通知/查单结果为准。

### 4.8 用户、投诉与审核

- 用户列表、积分余额和流水只读查看、收藏/解锁数量。
- **多管理员账号**：超级管理员可创建、禁用其他管理员账号；一期所有管理员权限相同（不细分配权），数据模型预留 `role` 字段供后续扩展。安全基线：密码哈希、登录限速、会话失效、CSRF/CORS。
- 版权投诉与举报统一入口（`Complaint`，类型区分侵权/违规/其他）：记录投诉者、资源 ID、联系信息、投诉说明、证明材料引用、提交时间和处理状态；提供下架、恢复、驳回和处理记录。
- 意见反馈管理：查看、标记处理状态、回复内容。
- 每次审核/发布/下架/积分调整/系统配置变更写审计日志（操作者、时间、动作、资源/配置、变更摘要；日志内容对网盘链接等敏感字段脱敏）。
- 通知触达：个人开发者不做订阅消息/推送；投诉结果、反馈回复由用户主动进入小程序查看。

### 4.9 系统配置

必须实现以下配置（配置从后端读取，前端不得自行决定付费规则）：

- `monetizationEnabled`：积分商业化总开关。关闭时所有正常发布资源有效价格按 0 处理，不扣积分、不充值；保留真实价格字段、积分余额、历史订单和解锁记录。
- `virtualPayEnabled`：虚拟支付开关。关闭后不显示/不允许提交充值，不影响已经持有的积分在积分模式开启时消费。
- `checkinEnabled`、`checkinRewardEnabled`：签到入口与签到奖励发积分开关。免费模式下强制无积分奖励。
- `shareRewardEnabled`、`shareRewardCredits`、`shareRewardDailyLimit`：分享奖励开关与规则。
- `searchEnabled`、`favoriteEnabled`、`shareEnabled`：对应功能开关可选。
- 热搜推荐词列表（冷启动与运营位）。
- `copyrightDisclaimer`、`termsVersion`、`privacyPolicyVersion`：用户可见协议及版本。
- `homeSections`：首页模块配置。**可配置边界**：每个模块的开关、顺序、标题、展示数量、指定模板/合集；**不可配置**：任意页面搭建、自定义组件、任意样式。

开关配置变更即时生效，并记录日志。后端必须在所有价格计算、下单、扣积分和返回资源链接的接口内校验，不能只在 UI 隐藏按钮。

## 5. 免费/积分模式状态规则

| 条件 | 模板详情表现 | 充值表现 | 积分操作 |
|---|---|---|---|
| 积分模式关闭 | 所有正常发布资源免费显示资源链接 | 隐藏/禁用 | 不充值、不扣分、不发签到/分享积分；余额和流水保留 |
| 积分模式开启，虚拟支付关闭 | 免费模板直接获取；付费模板按积分解锁 | 充值入口关闭 | 可用已有积分消费，签到/分享按奖励开关发分 |
| 积分模式开启，虚拟支付开启 | 免费模板直接获取；付费模板按积分解锁 | 展示已启用、已核验 SKU | 正常按服务端规则充值/消费 |

额外规则：

- 免费模式只覆盖"有效公开资源"的价格，不自动发布草稿、不恢复被下架资源、不解除版权封禁。
- 切换免费模式不得更改数据库中的 `baseCreditPrice`；只计算 `effectiveCreditPrice`。
- 用户已解锁资源时，即使价格变化仍可访问；未解锁用户按新价格计算。
- 系统关闭充值期间，已经发起且尚未明确终态的支付订单仍需接受回调并正确入账/记录，不能因为开关关闭就丢弃合法支付通知。关闭开关只阻止创建新订单。
- 如果将来永久停止积分业务，必须另行处理已购积分及用户通知，不能直接删除余额。

## 6. 虚拟支付配置与技术要点

### 6.1 两处后台的职责

**微信公众平台（外部平台配置）**

- 小程序 AppID：`wx5f21980e48e92ae6`；服务类目"工具"（已选）；个人主体"虚拟支付"入口已确认可见（已开通路径畅通）。AppSecret 与虚拟支付 OfferID/AppKey 只存服务器环境变量。
- 在"虚拟支付 → 基本配置"获取 OfferID、现网 AppKey（以及测试所需配置）。密钥仅在后端环境变量中保存。
- 在"虚拟支付 → 道具管理"创建并发布积分充值商品；记下每个商品的 `productId` 和价格（单位为分）。
- 配置发货通知/消息推送 URL、Token、EncodingAESKey/加密方式，按官方文档进行联调。

**万用模板自己的管理后台（业务配置）**

- 配置商品名称、业务 Key、微信道具 ID、价格（分）、充值积分、赠送积分、说明、排序、启用状态、活动角标。

**概念区别**：微信后台道具是"充值积分包"；模板的积分价格仅在万用模板数据库中设置。不需要对每个模板在微信后台创建道具。

### 6.2 支付完整流程

1. 小程序请求服务端获取当前可购买的 SKU 列表。
2. 用户选择 SKU，小程序只提交 `skuKey`，服务端校验 `monetizationEnabled`、`virtualPayEnabled`、SKU 启用和映射核验状态。
3. 服务端创建唯一商户订单，使用服务端配置的 OfferID/AppKey 生成虚拟支付所需参数与签名。
4. 小程序调用 `wx.requestVirtualPayment`。
5. 微信向后端配置的回调接口推送支付/发货事件；后端验签、解密、验证 SKU/金额/订单/用户并进行幂等入账。
6. 小程序轮询服务端订单状态，只有后端确认已支付并发放积分后才更新界面。
7. 回调丢失时后端查单或通过管理端对账任务补偿；所有补偿操作幂等。

支付安全要求：AppKey/AppSecret/AI Key 不得进入小程序包、前端环境变量、浏览器 Bundle 或 Git 提交；价格、积分数不得信任客户端输入；支付回调要校验签名、金额、商品 ID、订单号和 openid 归属；订单号与平台交易号建立唯一索引；完整保留支付原始必要字段与审计记录。

### 6.3 充值档位约束

- SKU 定价统一以"分"存储，避免浮点金额运算。
- iOS 规则、最低金额、版本要求、沙箱可用性和服务费等以微信/苹果当前官方规则为准；充值档位需先核对平台要求，不能只用安卓测试通过作为验收。
- 当前文档不预设具体充值金额和积分比率，全部由管理员在微信平台创建商品后，再在本系统中配置匹配关系。

## 8. 后端模块

建议 NestJS 按业务模块拆分：

- `payments`：充值 SKU、订单、签名参数、回调、查单、补单、退款/投诉事件记录。
- `uploads`：上传批次、文件和网盘资源适配器（夸克/百度）。
- `ai`：模型适配器、JSON Schema 校验、提示词管理。
- `preview`：图片缩略图生成、上传图片校验。
- `tasks`：BullMQ 任务、重试、死信/失败任务管理、热度分预计算。
- `feedback`：用户意见反馈。
- `announcements`：系统公告。
- `admin`：资源审核、用户、订单、设置、统计、投诉、反馈、公告、审计日志、管理员账号管理。
- `system-config`：服务端开关与配置快取/即时更新。

资源链接 API 必须按模板状态和访问模式动态返回字段：免费模式/免费模板/已解锁用户可获得分享链接；其他情况只返回预览、价格和状态。列表和搜索 API 永远不返回完整网盘分享链接。

## 9. 数据模型（概念）

- `User`：openid、昵称/头像（可选）、状态、创建时间。
- `Template`：标题、摘要、封面、格式、状态、版权来源、授权声明、基础积分价、发布时间、热度分快照、元信息。
- `TemplateFile`：模板 ID、文件名、格式、大小、网盘类型、网盘文件 ID、预览地址、**分享链接（敏感字段，自带提取码）**。
- `Category`：分类维度、父 ID、名称、slug、排序、启用状态。
- `Tag`、`TemplateTag`、`TemplateCategory`：标签和多维分类关联。
- `Favorite`：userId + templateId 唯一约束。
- `ViewHistory`：userId、templateId、最后浏览时间；保留 200 条/90 天，定时清理。
- `CreditAccount`：userId、可用余额、乐观锁版本。
- `CreditLedger`：userId、流水类型、变更量、变更前后余额、关联订单/模板/签到/分享、幂等键、原因、时间；不可变追加记录。
- `CheckinRecord`：userId + date 唯一约束、奖励积分、连续天数快照。
- `ShareReward`：分享者 userId、被分享模板 ID、接收者 userId、唯一约束（分享者+模板）防重复计奖、关联流水幂等键。
- `PaymentSku`：业务 key、平台 productId、平台价格（分）、发放积分、赠送积分、启用/映射核验状态、排序、活动角标 `badgeText`、活动说明 `activityNote`。
- `PaymentOrder`：商户单号、userId/openid、SKU 快照、金额分、积分数量快照、状态、平台交易号、通知/查单信息。
- `TemplateUnlock`：userId + templateId 唯一约束、扣分数快照、来源订单/流水、解锁时间。
- `Feedback`：userId（可匿名）、类型（意见/问题/其他）、内容、联系方式（可选）、图片引用、状态（待处理/已处理）、回复内容、处理人、时间。
- `Announcement`：标题、内容、位置（首页公告条/我的页）、开始/结束时间、启用状态、排序。
- `SearchKeywordStat`：关键词（规范化小写）、近 7 天搜索次数（聚合计数，不关联具体用户）、更新时间；用于热搜词。
- `UploadBatch`、`ProcessingTask`、`ReviewRecord`：上传、AI/预览任务与人工审核轨迹。
- `Complaint`：资源 ID、投诉类型（侵权/违规/其他）、投诉信息、凭证引用、状态、处理记录。
- `SystemConfig`、`AdminUser`（含 `role` 字段）、`AdminAuditLog`、`Banner`。

**并发、幂等与时区约定：**

- MySQL 金额/积分全部用整数。
- **积分扣减**采用原子 SQL：`UPDATE credit_accounts SET balance = balance - :cost, version = version + 1 WHERE user_id = :uid AND balance >= :cost`，受影响行数为 0 即余额不足/失败；流水插入与该 UPDATE 在同一事务内。不依赖应用层先读后写。
- **幂等键规则**：充值入账 = 平台交易号 + 流水类型（唯一索引）；查单补单与回调走同一幂等键；签到 = `(userId, date)` 唯一约束；解锁 = `(userId, templateId)` 唯一约束；分享奖励 = `(分享者, 模板)` 唯一约束 + 流水幂等键；管理员调整 = 请求 requestId。
- **时区**：数据库一律存 UTC（Prisma 默认）；"自然日"等业务概念在应用层按 `Asia/Shanghai` 计算出日期字符串（DATE 列），不依赖 DB 时区设置。

## 12. 内容版权和免责声明

**内容供应策略：首批资源全部自制，首批规模 100 个模板**（覆盖主要分类：PPT、Word、Excel、教学课件、合同、手抄报、节日素材等），从源头规避第三方版权风险。后期如引入外部素材，必须逐条补充授权链条。

详情页免责声明仅用于说明资源用途、版权投诉渠道与用户责任，不能使未经授权的复制、上传、传播或收费行为自动合法化。必须实现：

- 上传者权利声明勾选与留痕。
- 管理员人工审核与审核记录。
- 投诉入口、投诉材料保存、处理期限配置（默认 3 个工作日内响应）、临时下架与恢复记录。
- 接到有效投诉后可迅速隐藏资源及停止返回网盘链接。
- 发生版权争议时保留相关资源 ID、来源与处置日志。

## 13. 安全与稳定性

- 微信登录只在服务器校验登录 code 并生成自身 session/JWT；openid 不由客户端随意指定。
- 所有管理员 API 需要管理员鉴权；写操作留审计日志。
- 对登录、搜索、签到、获取链接、下单、分享奖励上报、投诉、反馈接口限流。
- 上传文件做扩展名/MIME/大小校验；不执行文件、不加载远程文档中的脚本；上传图片处理（缩略图）使用受限临时目录和超时。
- DeepSeek API Key、微信 AppSecret、虚拟支付 AppKey、飞书 Webhook URL 只放服务器环境变量/密钥管理，不提交仓库。
- 所有外部 URL 做协议/域名验证，防止 SSRF；网盘 API 通过服务端适配器调用。
- 资源详情的链接字段不默认暴露；免费模式只通过详情的权限接口返回。审计日志、错误堆栈、告警消息中对网盘链接做脱敏处理。
- 重要数据库表设置备份策略、迁移脚本和恢复演练。
- 任务队列设置并发上限、失败重试和失败任务管理，防止大量批量上传耗尽内存或 API 额度。
- 异常通过飞书群机器人告警（见 7.1），关键事件：支付对账差异、任务失败超阈值、5xx 率、队列积压、磁盘水位。

## 14. 验收标准

### 资源与 AI

- 上传资源默认不公开；AI 可以生成分类候选与建议价格，但必须通过人工审核才能发布。
- AI 接口失败可重试，不重复生成公开资源，不丢失上传记录。
- 支持单文件和多文件模板；每条模板可配置封面 + 1–5 张预览截图，详情页正常浏览，图片缩略图正常生成。
- 分类筛选支持多维分类组合，管理员修改分类后列表与详情即时一致。

### 积分与模式切换

- 免费模式下正常发布模板全部可免费获得链接，不扣分；未发布/下架/封禁资源仍不可见。
- 积分模式下免费模板不扣分，付费模板余额不足时不能解锁；扣分成功后有永久解锁记录。
- 连续快速点击、并发请求或重复请求不会重复扣积分或造成负余额（原子扣减 + 唯一约束验证）。
- 分享奖励防刷：同一分享者同一模板只计一次、每日上限生效、伪造分享打开请求不计奖。
- 关闭/开启模式不改变 base price、历史余额、流水、订单及已解锁记录。
- 虚拟支付开关关闭后不能发起新充值订单；既有有效支付回调仍正常被处理。

### 虚拟支付

- 微信后台每个启用 SKU 均已创建并发布；本地 `productId` 与平台商品 ID 一致，价格以"分"精确一致。
- 模拟重复回调不会重复入账；支付通知丢失可查单补偿；客户端伪造价格/积分无效。
- 未配置 OfferID/AppKey/回调或 SKU 映射未核验时，支付入口保持关闭并显示可诊断错误。
- 对计划支持的 iOS/Android 微信版本完成真实设备测试，按平台现行版本及金额规则检查。

### 权限和合规流程

- 版权投诉能登记、通知管理员、下架资源、记录处理过程。
- 管理员发布资源时必须确认版权来源/授权声明。
- 隐私政策、用户协议、免责声明和反馈渠道可在小程序访问。

### 工程质量

- `npm ci` 后可通过 workspace 脚本启动 API、管理端和小程序编译。
- CI 通过类型检查、lint、Prisma schema 校验、单元/集成测试、`miniprogram:check` 编译校验。
- 提供 `.env.example`、数据库迁移、开发环境 compose、部署说明、初始化管理员脚本和上线检查脚本。
