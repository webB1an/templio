## 二、当前并发

| 环节 | 并发 |
| --- | --- |
| 桌面端生成任务 | 同一时间 **1 个任务** |
| CLI 内部渲染 | 默认 **2 个 LibreOffice 并发**（`--concurrency 2`） |
| 物料上传 | **严格串行，1 个物料包上传完再传下一个** |
| 服务端导入 | 每个请求串行处理，不并行写图片 |
| 网盘同步 | 同一模板已加锁；不同模板目前**没有全局并发上限** |

建议：84GB 合集渲染保持并发 2；遇到几百 MB 的 PPTX 如果本机内存吃紧，用 CLI 降到 `--concurrency 1`。网盘同步不要一次点多条，按批一条条跑。

## 三、当前会遇到的硬性问题

### 1. 84GB 源文件不能一次性上传服务器

服务器：

- 总磁盘 40GB，已用 13GB，**剩余约 25GB**
- 当前 storage 只有 364KB

84GB 源文件远超服务器剩余空间，而且服务端刚加了 **8GB 源文件中转限额**（`INCOMING_QUOTA_GB=8`）。一次性勾选「同时上传源文件」上传全部，会在中途被拒绝或把磁盘写满。

### 2. 本地输出空间

CLI 生成物料包时会把源文件放进 `source/`。

- 已改为 **同磁盘优先硬链接**：源文件已经在 C 盘时，物料包里的 `source/` 不再额外复制 71.9GB
- 只有图片是新生成的，约 1–2.3GB（取决于每个模板 1–4 张预览）
- 因此本地 17.3GB 可用空间处理全部图片包可以承受；跨磁盘输出会回退成复制，需要另算空间

### 3. 85 个源文件超过 80MB

服务端单文件上限 80MB，这些模板的源文件不能走「同时上传源文件」：

- 可以只上传封面/缩略图/预览图（不传 source）
- 或手动传到网盘、在管理端填写链接
- 不能自动同步，因为服务器没有源文件

### 4. 旧格式与损坏文件

- 154 个 `.ppt`、9 个 `.doc` 不会进入当前扫描，需要先用 LibreOffice 转成 `.pptx/.docx`
- 14 个零字节 `.pptx` 会渲染失败，建议先删除/修复

### 5. 网盘同步工作量

4,806 个模板全部同步到网盘，意味着：

- 4,806 次服务端源文件上传
- 4,806 次网盘上传 + 分享
- 4,806 次短链写入
- 4,806 次管理端复核/AI 标注/上架

按单个任务十几秒到几十秒估算，这是一项需要数天、且需要限制并发和接受失败重试的批处理任务，不适合在管理端一条条点。

## 四、建议的批次方案

### 批次上限

- 每批源文件总量控制在 **3–4GB**
- 上传服务器时勾选源文件
- 每批同步完网盘后确认源文件已删除，再上传下一批
- 所有批次共用图片包时，服务端图片总量约 1–2.3GB，放得下

71.87GB 里排除 84 个超过 80MB 的源文件（12.85GB）和 11 个零字节文件后，可自动处理部分为 **4,711 个 / 59.02GB**。

### 单批流程

已提供批处理脚本：

```powershell
# 生成 + 上传（带源文件）+ Quark 同步
node scripts/run-batch.mjs --batch b001

# 默认同步后保持 imported；需要直接上架加 --publish
node scripts/run-batch.mjs --batch b001 --publish
```

脚本会串行上传和同步，失败项会写入 `templio-batches\reports\` 下的 JSON 报告。

手工流程与脚本等价：

1. 建一个批次源目录，只放进本批 `.pptx/.docx`
2. 桌面工作台选择该批次目录
3. 输出目录单独设置（例如 `dist-batch-01`）
4. 生成；检查日志里的失败项
5. 点击「上传到服务器」，勾选「同时上传源文件」
6. 到管理端对这批模板做网盘同步/复核
7. 源文件同步删除后，删除本地该批物料包，继续下一批

### 不建议的做法

- 不要把 84GB 根目录直接选择后一次性生成 + 一次上传全部源文件
- 不要同时开多个上传/同步任务
- 不要在没有清理源文件的情况下连续上传多批
- 不要指望一次性把 4,806 个模板人工上架，需要先做批处理脚本或只挑选精品模板

## 五、结论

- **只上传图片、不上传源文件**：数据量约 1–2.3GB，服务器空间足够，但无法自动同步网盘。
- **源文件 + 自动网盘同步**：必须按 3–4GB 分批，已拆成 17 批；全部处理完需要较长时间和人工/脚本配合。
- 当前代码已做两项保护：同盘源文件硬链接、服务端 8GB 源文件配额；但仍建议按批次操作。
