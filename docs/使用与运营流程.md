## 0. 系统构成

三个端 + 一套 API，数据全部落同一个 MySQL 库 `templio`。

```
┌──────────────┐        ┌──────────────┐
│ 微信小程序    │        │ 管理后台      │
│ 用户浏览/解锁  │        │ 运营录入/审核  │
└──────┬───────┘        └──────┬───────┘
       │ /api（用户 JWT）        │ /api/admin（管理员 JWT）
       └───────────┬───────────┘
                   ▼
          ┌─────────────────┐
          │  NestJS API     │  127.0.0.1:3000
          └────┬───────┬────┘
               │       │
        ┌──────▼──┐  ┌─▼──────────────┐
        │ MySQL   │  │ 网盘（夸克/百度）│
        │ templio │  │ CLI 上传+分享   │
        └─────────┘  └────────────────┘
               │
        ┌──────▼──────┐
        │ DeepSeek AI │  标题/分类/标签/定价建议
        └─────────────┘
```

| 入口 | 地址 |
|---|---|
| 小程序 | 微信搜索「万用模板」（AppID `wx5f21980e48e92ae6`） |
| 管理后台 | `https://templio.wdbzk.com/admin/` |
| API | `https://templio.wdbzk.com/api` |
| 宝塔面板 | `https://47.111.99.7:42086/ec618a07` |
| 健康检查 | `GET /api/health` → `{"status":"ok","db":"up"}` |

## 1. 角色与权限

| 角色 | 进入方式 | 能做什么 |
|---|---|---|
| 小程序用户 | 微信授权登录（`wx.login` → openid → 用户 JWT） | 浏览、搜索、签到、充值、解锁、收藏、分享 |
| 管理员 `admin` | 账号密码 | 资源管理、分类标签、网盘、订单积分、投诉、系统配置 |
| 超管 `super` | 同上（`role=super`） | 上述全部 + 管理其他管理员账号 |

管理员账号在「系统配置 → 用户管理」或 `npm run admin:seed` 初始化。

## 2. 小程序端用户流程

底部 4 个 Tab：**首页 / 分类 / 积分 / 我的**，另有 2 个二级页：**模板详情 / 搜索**。

### 2.1 首次进入与登录

- 进入页面不强制登录，首页、分类、搜索可直接浏览。
- 触发登录的时机：签到、充值、解锁付费模板、进入「我的」。
- 登录链路：`wx.login()` 取 code → `POST /api/users/wx-login` → 后端 `code2session` 换 openid → 建/查用户 → 签发用户 JWT（存本地 `templio_user_id`）。
- **静默登录**：不弹昵称头像授权，openid 即身份。

### 2.2 首页

三个接口并行拉取（拆分是为了各自独立缓存）：

| 接口 | 内容 |
|---|---|
| `GET /api/home/overview` | 顶部数据概览（模板总数等） |
| `GET /api/home/banners` | 轮播图，点击跳内部模板/分类或外链 |
| `GET /api/home/sections` | 热门榜（按 `heatScore`）+ 最新上架 |

热度分 = 浏览 ×1 + 收藏 ×8 + 分享 ×2，由后台预计算，不实时算。

支持下拉刷新；搜索框回车跳搜索页。

### 2.3 分类

- `GET /api/categories/tree` 取两级分类树。
- 四个维度：**格式 / 场景 / 人群 / 主题**，每个维度下挂二级分类。
- 点二级分类进入该分类下的模板列表。

### 2.4 搜索

- `GET /api/templates/search?q=`，MySQL ngram FULLTEXT 匹配标题与摘要。
- 支持从首页/分类页带关键词进入。

### 2.5 模板详情与解锁（核心转化点）

详情页拿到 `GET /api/templates/:id` 后，按钮文案由三种状态决定：

| 状态 | 判定 | 按钮 | 点击行为 |
|---|---|---|---|
| 免费 | `detail.free === true` | 「免费获取」 | 直接出网盘链接 |
| 已解锁 | `detail.unlocked === true` | 「已获取 · 查看链接」 | 直接出网盘链接 |
| 需积分 | 两者皆否 | 「`N` 积分解锁」 | 余额够则扣积分解锁；不够弹窗引导去积分页 |

解锁链路：

```
点击解锁 → 未登录先登录 → POST /api/credits/unlock/:id
        → 服务端原子扣减（余额不足返回错误）
        → 成功则重新加载详情（此时 unlocked=true，不再二次弹窗）
        → 展示「获取链接」按钮
```

> 已修 Bug：早期版本解锁后靠 `free` 判断导致递归死循环，现统一判 `detail.unlocked`。

**获取链接**：`GET /api/templates/:id/share-links` 返回该模板所有网盘文件的可复制链接，点击复制到剪贴板。链接来自网盘永久公开分享，不占用 CDN。

**分享**：右上角分享卡片路径带 `?sharerId=<我的用户ID>`，好友打开即触发 `POST /api/credits/share-event` 给分享者计奖。

### 2.6 积分页（签到 + 充值 + 流水）

一页三块：

1. **余额卡**：`GET /api/credits/account`。
2. **签到**：`POST /api/credits/checkin`
   - 每日 1 次，默认 +10 分（后台可配）；当天已签到按钮置灰。
   - 后台关闭「每日签到」开关后，接口返回「活动暂未开放」，不再发分。
3. **充值**：`GET /api/pay/skus` 拉充值项 → 下单 `POST /api/pay/orders`
   - **当前为 MOCK 支付模式**（`MOCK_PAY=true`）：下单后调 `POST /api/pay/mock-pay/:orderNo` 直接置为已支付、加积分。
   - 正式上线需接 `wx.requestVirtualPayment`，并在服务器 `.env` 把 `MOCK_PAY` 改为 `false` 重启。
4. **积分流水**：`GET /api/credits/ledger`，含获得/消耗明细与时间。

积分规则默认值（「系统配置 → 积分规则」可改，保存即生效）：

| 项目 | 默认 | 说明 |
|---|---|---|
| 每日签到 | 10 分 | 关闭开关后停发 |
| 单次分享奖励 | 5 分 | 好友通过分享链接打开才计 |
| 分享者单日上限 | 50 分 | 防刷，服务端强制 |
| 解锁扣减 | 模板定价 | 原子 SQL，余额不足直接失败 |

### 2.7 我的

- 展示昵称/头像/积分余额，`GET /api/users/me` + `/api/credits/account`。
- 入口：我的积分（跳积分 Tab）、我的收藏、历史浏览。
- 未登录时展示登录引导。

## 3. 管理端运营流程

### 3.1 登录与工作台

- 地址 `https://templio.wdbzk.com/admin/`，账号密码登录，token 存 localStorage。
- **工作台**四张卡：资源总数 / 待审核 / 已发布 / 已驳回，点数字可跳到对应筛选列表。

左侧菜单 7 项：工作台、资源管理、分类标签、网盘管理、订单积分、用户投诉、系统配置。

### 3.2 首次使用：必须先做的 4 件事

新环境上线后**按顺序**完成，否则内容生产链会断：

**① 配网盘账号（「网盘管理」）— 硬前置**

批量导入没有网盘账号会直接 400 拒绝，不产生任何数据。

| 步骤 | 夸克 | 百度 |
|---|---|---|
| 1 | 新增账号 → 选「夸克网盘」→ 填名称 | 新增账号 → 选「百度网盘」→ 填名称 |
| 2 | 点「授权」→ 打开授权页 → 复制授权码 → 粘贴回弹窗 | 点「配置 Cookie」→ 浏览器登录 pan.baidu.com → F12 → Network → 复制整段 Cookie（需含 BAIDUID） |
| 3 | 点「探测」确认状态为「正常」 | 同左 |
| 4 | 点「设默认」 | 同左 |

- 每个账号的授权态**独立隔离**，凭证只写在服务器该账号的独立文件中，不进数据库、不进 git。
- 「网盘管理」只负责账号本身。**文件上传与分享不在这里做**，由批量导入/模板编辑自动完成。
- 夸克上传免提取码、体验更好，建议优先用夸克。

**② 建分类（「分类标签」）**

- 先建一级分类（选维度：格式/场景/人群/主题），再建二级。
- 至少准备 1 个可用的二级分类，否则模板无法提审。

**③ 配充值项（「订单积分 → 充值项」）**

- 新建 SKU：`skuKey`、名称（如「100 积分」）、积分数量、赠送积分。
- 小程序积分页实时读取，无需发版。

**④ 检查开关（「系统配置」）**

- 每日签到、分享奖励开关；签到/分享积分数值与日上限。
- 顶部的 mock 支付告警说明当前仍是模拟支付。

### 3.3 批量导入（内容生产主流程）

**入口**：资源管理 → 右上「批量导入」

**操作**：把模板原文件拖进虚线框 → 设置参数 → 点「开始导入」。

参数说明：

| 参数 | 默认 | 说明 |
|---|---|---|
| 目标网盘 | 自动（默认账号） | 可强制指定夸克/百度 |
| 预览页数 | 6 | 1–20，只对 PDF 生效 |
| 自动补全 | 开 | AI 生成标题/摘要/分类/标签/建议价 |
| 完成后自动提审 | 开 | 关掉则只留草稿，人工再提 |

**限制**：单文件 ≤300MB，一次最多 50 个，一个文件 = 一个模板。

**后端自动跑完 6 个阶段**（串行队列，页面每 2.5 秒轮询进度）：

| 阶段 | 进度 | 实际动作 |
|---|---|---|
| `render` | 10% | 生成首图与预览图（见下方格式差异） |
| `create` | 30% | 建模板草稿，回填封面与预览图 |
| `upload` | 45→55% | 上传原文件到默认网盘，生成**永久公开**分享链接，落 TemplateFile |
| `ai` | 75% | DeepSeek 视觉识别 → 标题/摘要/二级分类/标签/建议积分价 |
| `submit` | 92% | 信息完整则自动提审（进入待审核） |
| `done` | 100% | 完成 |

**不同格式的预览图行为**（重要，影响导入策略）：

| 格式 | 首图来源 | 预览页数 |
|---|---|---|
| **PDF** | `pdftoppm` 逐页渲染 | 多页（按「预览页数」设置）✅ 效果最好 |
| PPTX / DOCX / XLSX（2007+） | 解包取 `docProps/thumbnail` 内置缩略图；没有则取 `ppt/media` 最大图 | 只有 1 张 |
| 图片（png/jpg/webp） | 直接当首图 | 1 张 |
| 旧版 ppt / doc / xls（OLE） | 取不到 | 无，需人工补封面 |

> **实践建议**：想要多页预览就先把文件导出成 PDF 再导入，PPTX 直接导入只有 1 张封面。

**失败与重试**：

- 每条任务是独立的，一条失败不影响其他。
- 失败会在行内显示红色原因（如「未配置默认网盘账号」）。
- 点「重试」从**断点继续**：已完成的阶段（预览图、建草稿、已上传的分享链接）不会重做，不重复消耗 AI。
- 服务重启（含部署）时，正在跑的任务自动回队重跑，不会卡死。

**导入完成后**：点「去资源管理」看 `待审核` 列表，人工终审。

### 3.4 单条精细制作

**入口**：资源管理 → 「新建模板」或点列表标题进入编辑页。

流程：

```
填写标题/格式/积分价/摘要
  → 上传封面（1 张，自动转 webp）
  → 上传预览截图（最多 5 张，可点开预览大图）
  → 选两级分类（可多选）+ 标签
  → （可选）上传模板原文件：自动生成首图/预览图 + 上传网盘 + 生成分享链接，一并回填
  → （可选）点「AI 补全」：上传封面截图后自动填标题/摘要/分类/标签/建议价
  → 保存（草稿）
  → 提审
```

- **AI 补全**：`POST /api/admin/templates/:id/ai-enrich`，模型 DeepSeek `deepseek-flash`，读封面/预览图 + 现有元信息，输出建议。**只填表单，必须人工确认后保存**；发布与定价始终人工把关。未配 `DEEPSEEK_API_KEY` 时返回「AI 辅助分类不可用」。
- **上传原文件**：`POST /api/admin/templates/publish-file`，一步完成「渲染预览图 + 传网盘 + 生成链接 + 回填」。建议优先夸克。

### 3.5 审核与状态流转

**状态机**（后端强校验，非法跳转直接报错）：

```
draft ──提审──▶ pending_review ──通过──▶ published ──下架──▶ offline
  ▲                    │                                        │
  │                  驳回                                       │
  └────rejected ◀──────┘                                        │
                        └──────────重新提审───────────────────────┘

banned（封禁）：不进自动流转，仅管理端人工处理
```

**提审前必须满足 3 个条件**（缺一条报错）：

1. 有封面图
2. 至少 1 个网盘文件
3. 至少 1 个分类

**列表页操作**：

| 按钮 | 适用状态 | 作用 |
|---|---|---|
| 查链 | 任意 | 批量检测网盘分享链接是否有效，显示「可用/总数」 |
| 提审 | draft / rejected | 校验三要素后进入待审核 |
| 通过 | pending_review | 发布，记录发布时间 |
| 驳回 | pending_review | **必须填原因**，原因会回显给运营 |
| 下架 | published | 转 offline（投诉下架与主动下架共用） |
| 编辑 / 删除 | 删除仅 draft / rejected | — |

批量能力：勾选多行 → **批量提审** / **批量通过**（逐条容错，返回成功与失败明细）。

### 3.6 日常运营

**订单积分**（三个 Tab）

| Tab | 用途 |
|---|---|
| 充值订单 | 查订单号、用户、金额、积分、状态；待支付订单可「关闭」 |
| 充值项（SKU） | 增改积分包，小程序即时生效 |
| 人工调账 | 填用户 ID + 数额（正加负扣）+ 原因，用于补偿/退款 |

**用户投诉**（`/admin/users`）

- 列表按状态筛：待处理 / 已处理 / 已驳回。
- 点「处理」选择结果并填处理说明。
- 涉及违规内容时，配合到资源管理「下架」该模板。

**分类标签**

- 分类维度的**创建后不可改**（编辑时维度禁用），只能改名称、排序、启用状态。
- 停用分类后不能再被选入模板，且提审时会校验分类有效性。

**系统配置**

- 功能开关：签到、分享奖励（切换即存即生效）。
- 积分规则：签到分值、分享分值、分享日上限。
- 支付模式只读展示当前是 MOCK 还是微信虚拟支付。

## 4. 技术运维流程

### 4.1 代码上线（全自动）

推送到 `main` 即触发 GitHub Actions CD：

```
push main
  → CI（ubuntu）npm ci → prisma generate → build
  → 打包产物 tar 上传到服务器 /www/templio/releases/
  → 服务器解包（.env / logs / node_modules 不受影响）
  → 依赖指纹变化才 npm ci（1.6G 内存扛不住每次装）
  → prisma generate（无条件）+ prisma migrate deploy（无条件）
  → 同步管理端静态文件到 /www/wwwroot/templio/admin
  → pm2 delete + pm2 start（必须重建进程，否则 .env 变更不生效）
  → curl /api/health 自检，输出 DEPLOY_OK
```

### 4.2 数据库迁移

- 迁移文件：`apps/api/prisma/migrations/`，CD 时自动 `migrate deploy`。
- 本地手动迁移走安全脚本（**先备份再迁移**）：

```bash
npm run tunnel:db        # 另开窗口保持隧道
npm run prisma:migrate   # = safe-migrate.sh dev
```

### 4.3 备份

```bash
npm run db:backup        # mysqldump → 服务器 /www/backup/templio-时间戳.sql.gz
```

迁移前**必须**先备份（`safe-migrate.sh` 已内置）。

### 4.4 服务器重启后

| 服务 | 是否自启 |
|---|---|
| nginx | 是 |
| 宝塔面板 | 是 |
| MySQL | 是 |
| **templio-api（PM2）** | 是（已配 `pm2-root` systemd 自启 + `pm2 save`） |

若发现 API 没起，依次查：`systemctl status pm2-root` → `pm2 list` → `pm2 start ecosystem.config.js`。

### 4.5 故障排查速查

| 现象 | 排查顺序 |
|---|---|
| 网站 502 | `pm2 list` 是否 online → `pm2 logs templio-api` 是否启动报错 → `/api/health` |
| 面板打不开 | **先带浏览器 UA 验证**：裸 curl 会被面板的爬虫过滤拦成 404，看着像挂了其实正常 |
| 导入全部失败 | 网盘管理是否有账号且「设默认」→ 点「探测」看授权是否过期 |
| 预览图为空 | 旧版 ppt/doc/xls 无法提取，需人工补封面；PPT 建议先导 PDF |
| AI 补全报不可用 | 服务器 `.env` 是否配 `DEEPSEEK_API_KEY` |
| 图片打不开（127.0.0.1） | 媒体 URL 规范化层会重写为 `https://templio.wdbzk.com`，检查 `PUBLIC_BASE_URL` |

### 4.6 硬性约束（务必遵守）

- 服务器只有 **1.6G 内存**：**严禁安装/运行 LibreOffice**（曾因装它把整机拖死，只能控制台强制重启）。文档预览一律走零依赖方案：PDF → `pdftoppm`；Office → `unzip` 提取内置缩略图。
- 服务器上不在本地编译：构建全在 CI，服务器只解包。
- `.env` 变更后必须 `pm2 delete + start`，`pm2 reload` 读不到新值。
- 密码/密钥只放 `.env`，不进 git、不写进文档。

## 5. 关键规则速查

| 项目 | 规则 |
|---|---|
| 模板状态 | draft / pending_review / published / rejected / offline / banned |
| 提审三要素 | 封面 + ≥1 网盘文件 + ≥1 分类 |
| 驳回 | 必须填原因 |
| 批量导入上限 | 50 文件 × 300MB，预览 1–20 页 |
| 编辑页图片 | 封面 1 张，预览截图最多 5 张 |
| 积分扣减 | 原子 SQL，余额不足直接失败 |
| 分享奖励 | 好友经分享链接打开才计，单日封顶可配 |
| 签到 | 每日 1 次，可后台关闭 |

## 6. 已知限制

1. **旧版 Office（.ppt/.doc/.xls）**：OLE 二进制格式，取不到内置缩略图，导入后无封面，需人工补。
2. **PPTX/DOCX 只有 1 张预览图**：要多页请先导出 PDF。
3. **模拟支付**：真实虚拟支付未接入，小程序充值目前是假支付。
4. **分享防刷依赖服务端**：日上限已强制，但同一用户换设备仍是同一 openid 计一次。
5. **单库共库**：开发测试直连线上库，操作需谨慎，迁移前必须备份。
