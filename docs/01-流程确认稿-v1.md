### 0.1 一个必须说明的核实结果

你让我核实「夸克/百度官方网盘工具是否支持 Windows」：

| 网盘 | 官方工具 | Windows 原生 | WSL / macOS / Linux |
| --- | --- | --- | --- |
| 夸克 | `quarkclouddrive_offical`（官方 Skill） | ❌ | ✅ |
| 百度 | `bdpan-storage`（百度网盘官方 Skill，命令即 `bdpan`） | ❌ | ✅ |

两个官方工具都**明确不支持 Windows 原生**，只支持 macOS/Linux/Windows(WSL)。而本机当前连 WSL 发行版都没有。

**因此采用方案 A**：把「传网盘」从桌面挪到服务端。桌面只负责渲染和上传物料，服务端（Linux）用官方 Skill 完成百度/夸克上传与分享。这与 wallpaper-manager 现有链路完全一致，且不影响你想要的结果——**管理端上架时，网盘链接已经就绪**。

## 1. 产品定义（一句话）

**Templio 是一个 PPT/Word 模板库小程序：用户在微信里浏览、搜索、收藏模板，通过网盘短链拿到源文件；运营用桌面批处理工具 + Web 管理端批量上架模板。**

三个角色：

- **运营（你）**：桌面 CLI 批量出物料 → 上传 → 在 Web 管理端复核上架。
- **用户**：小程序浏览 → 详情页复制网盘短链 → 网盘下载 → 电脑使用。
- **系统**：接收物料、同步网盘、AI 生成标题/分类、发短链、提供公开 API。

## 4. 端到端流程

### 4.1 供给链路（运营侧）

```
① 运营把 pptx/docx 按分类放本地目录
        │
② templio render（桌面 CLI）
        │  sha256 去重 → 抽文字 → LibreOffice 转 PDF → PDF 转图 → 裁剪物料
        ▼
   dist/<hash8>-<slug>/  标准物料包（manifest + 源文件 + 封面/缩略图/预览 + 文字）
        │
③ templio upload
        │  preflight（按 hash 查重）→ 分片上传 → 逐包 commit
        ▼
④ 服务端：创建 Template(status=imported)，入队两个任务
        │
        ├── netdisk_sync：源文件传百度/夸克 → 永久分享 → 拿链接+提取码 → 生成短链
        │
        └── ai_classify：DeepSeek（封面 + 前 3 页 + 文字）→ 标题/分类/标签/简介
        │
⑤ 管理端 Web：待复核队列 → 人工核对（改标题/分类/标签/链接）→ 批量上架
        │
⑥ 小程序可见
```

**关键规则：**

1. **两任务并行**，但都完成且人工确认后才允许上架。
2. **幂等**：以 `sourceHash`（SHA-256）为唯一键，重复导入不重复建、不重复调 AI、不重复传网盘。
3. **失败可重跑**：AI 失败重试 3 次后转人工兜底；网盘失败进失败队列，管理端一键重跑。
4. **人工闸门**：不允许 AI 结果直接上架。
5. **源文件不长期留在服务器**：网盘同步成功并校验后，按策略（默认 7 天）清理；本地始终保留。

### 4.2 消费链路（用户侧）

```
打开小程序
  → 首页：搜索、分类入口、精选/最新瀑布流
  → 列表：封面瀑布流（3:4），分类/标签筛选，下拉刷新 + 上拉加载
  → 详情：
       · 封面大图 + 多页预览（3–6 张，可左右滑动）
       · 标题 / 格式 badge / 页数 / 大小 / 分类 / 标签
       · AI 生成的一句话简介 + 免责声明（小字）
       · 「获取模板」玻璃卡片：主网盘短链 + 提取码 + 一键复制（链接+提取码）
       · 收藏 / 分享
       · 「如何在电脑上使用」三步说明
       · 相关推荐
  → 复制短链 → 打开网盘 App/浏览器 → 保存到网盘 → 电脑端下载使用
```

**为什么是复制而不是跳转：** 小程序不能直接打开网盘链接（业务域名限制），wallpaper-manager 已验证「展示短链 + 提取码 + 复制按钮」是可行且可过审的做法。文案上要写清楚"复制后到网盘 App 打开"。

### 4.3 状态机

**Template 状态：**

```
draft ──导入──▶ imported ──有物料/链接──▶ ai_processing ──▶ pending_review ──人工──▶ published
                    │                          │                    │                    │
                    │                          └──失败──▶ failed ◀──┘                    │
                    └───────────────────────────────────────────────┬──────────────────┘
                                                                    ▼
                                                                 archived（下架）
```

> 简化说明：实际实现中 `netdisk_sync` 与 `ai_classify` 可并行；`pending_review` 的条件是「两个任务都结束」。失败状态保留错误原因，可从管理端重试。

**Task 状态：** `queued → running → success / failed / skipped`

**网盘链接状态：** `pending → synced → invalid`（失效检测，人工可标记）

**桌面本地包状态（记录在 dist 的 JSONL 账本）：** `rendered → uploading → uploaded / failed`

## 5. 标准物料包（三端唯一契约）

```
dist/<hash8>-<slug>/
├── manifest.json
├── text.json
├── source/<原文件名>.pptx|.docx
└── images/
    ├── cover.webp        # 1080×1440（3:4）
    ├── thumb.webp        # 600×800（3:4）
    └── preview-01.webp   # 宽 1080，取前 N 页
```

`manifest.json`：

```json
{
  "packageVersion": 1,
  "sourceHash": "sha256…",
  "sourceFile": "source/xxx.pptx",
  "sourceBytes": 1234567,
  "format": "pptx",
  "pageCount": 24,
  "titleGuess": "文件名清洗后的兜底标题",
  "images": {
    "cover": "images/cover.webp",
    "thumb": "images/thumb.webp",
    "previews": ["images/preview-01.webp", "images/preview-02.webp"]
  },
  "renderer": { "engine": "libreoffice", "version": "24.8", "pdfDpi": 144 },
  "generatedAt": "2026-11-01T10:00:00+08:00"
}
```

`text.json`：

```json
{
  "title": "从 OOXML core.xml / 首屏抽取",
  "outline": ["第一节标题", "第二节标题"],
  "firstPagesText": ["第一页文字…", "第二页文字…"],
  "slideCount": 24,
  "wordCount": 860
}
```

**图片规格（定死，后续不改）：**

| 图 | 尺寸 | 格式/质量 | 上限 | 数量 |
| --- | --- | --- | --- | --- |
| thumb | 600×800（3:4） | WebP q80 | ≤ 60KB | 1 |
| cover | 1080×1440（3:4） | WebP q85 | ≤ 200KB | 1 |
| preview | 宽 1080，等比 | WebP q82 | ≤ 150KB | 3–6 |

**封面构图规则（解决 PPT 16:9 裁成 3:4 会切内容的问题）：**

1. 背景：首屏渲染图放大 + 高斯模糊 + 压暗；
2. 前景：完整首屏等比缩放居中（加圆角/细边框/投影）；
3. 一期不加文字（纯渲染）；二期在预留的底部安全区合成标题/卖点。

## 8. 桌面 CLI 规格

### 8.1 技术选型

| 用途 | 方案 |
| --- | --- |
| 运行时 | Node ≥ 22（本机 24.15.0 ✅） |
| 命令解析 | `commander` |
| Office → PDF | **LibreOffice headless**（`soffice --headless --convert-to pdf`） |
| PDF → 图片 | `pdfjs-dist` + `@napi-rs/canvas`（纯 npm，无需额外二进制） |
| 图片处理 | `sharp`（缩放/裁剪/WebP/模糊背景） |
| OOXML 文字抽取 | `jszip` + `fast-xml-parser`（解 pptx/docx，无需装 Office） |
| 上传 | `undici` + 分片重试；本地账本用 JSONL |
| 校验 | `zod`（与 `packages/shared` 共享 manifest schema） |

### 8.2 命令

```bash
templio doctor                          # 检查 LibreOffice 路径/中文字体/API 连通/磁盘
templio render <srcDir> --out <distDir> # 批量渲染物料包
  --preview-pages 6   --dpi 144   --concurrency 2   --force
templio upload <distDir> --api https://api… --token <cliToken>
  --concurrency 3     --retry 3   --dry-run
templio status <distDir>                # 统计渲染/上传/失败数量
templio retry <distDir> --failed        # 重跑失败项
```

### 8.3 渲染管线（每个文件）

```
① sha256 → 查 dist 已有 manifest（同 hash 且完整）→ 跳过
② 解包 OOXML：抽标题/目录/前几页文字 → text.json
③ LibreOffice 转 PDF（每 worker 独立 UserInstallation 配置目录，避免锁冲突）
④ PDF → 页面 PNG（144 DPI，首屏 + 前 N 页）
⑤ sharp 生成 cover / thumb / preview（封面 = 模糊底图 + 完整首屏居中）
⑥ 写 manifest.json + 更新账本
⑦ 单文件失败：记录原因（soffice 超时/文件损坏/无文字），继续下一个；最后输出失败清单
```

### 8.4 上传策略

1. `preflight` 批量查询（一次传 100 个 hash，返回待传列表）；
2. 物料图（小文件）走 multipart 直接传；
3. 源文件走分片上传（默认 8MB/片，可配），服务端支持断点续传；
4. 每包 `commit` 后服务端立即入队；
5. 失败重试 3 次（指数退避），仍失败写账本，`templio retry --failed` 可续。

### 8.5 渲染质量兜底（必须做）

LibreOffice 对复杂版式/特殊字体一定会有漂移。给运营留后门：

- 管理端支持**替换封面/预览图**（上传自定义图，覆盖渲染结果）；
- 管理端支持**标记"渲染不可用"**，该模板可只显示封面、不显示多页预览；
- CLI 记录 `renderer` 与 `warnings`，供抽检筛选。

## 9. AI 标注规格

### 9.1 输入（不要只给封面）

| 输入 | 来源 | 作用 |
| --- | --- | --- |
| 封面图 | 物料包 | 视觉风格 |
| 前 3 页预览图 | 物料包 | 行业/场景判断 |
| `firstPagesText` | text.json | 最准的分类信号 |
| 格式/页数/文件名 | manifest | 硬事实 |
| 分类枚举 + 标签候选 + 最近标题样例 | 服务端注入 | 约束输出、避免同质化 |

> 视觉模型用 `deepseek-flash`（官方已支持图片输入，见 [Vision 文档](https://api-docs.deepseek.com/guides/vision/)）；API Key 只在服务端。

### 9.2 输出（zod 校验 + 枚举约束）

```ts
{
  title: string,          // 8–30 字，含关键词，不夸大
  subtitle?: string,      // ≤ 40 字
  category: CategoryKey,  // 必须命中枚举
  tags: string[],         // 3–8 个，每个 ≤ 8 字
  audience?: string,      // 学生/职场/教师/企业…
  style?: string,         // 商务/简约/中国风/科技…
  summary?: string,       // ≤ 80 字，一句话
  confidence: number,     // 0–1
  safe: boolean,
  flags: ("political"|"sexual"|"violence"|"vulgar")[]
}
```

### 9.3 工程处理

1. **标题去重**：与库内已发布标题比对（归一化后），重复则带不同 few-shot 重新生成一次；
2. **合规过滤**：极限词/敏感词词表拦截，命中则重写；
3. **失败兜底**：无 Key / 调用失败 / 结构不合法 → 用 `titleGuess`，分类=未分类，`needsReview=true`；
4. **重试**：3 次指数退避；记录 tokens 与耗时；
5. **调优闭环**：管理端记录"人工改后标题"，后续可作为 few-shot 样例；
6. **人工闸门**：`pending_review` 必须人工确认才能 `published`。

### 9.4 成本

按每模板 4 张图（每图上限约 1024 tokens）+ 文字，**1000 个模板约 400–500 万 input tokens 量级**，token 成本可控；真正的成本是复核时间。建议复核 UI 支持键盘连续操作 + 批量通过。

### 11.1 页面


### 11.2 液态玻璃设计规范

**原则（最重要）：** 玻璃只用于「浮在内容之上的控制层」——导航栏、TabBar、搜索条、筛选条、浮动按钮、弹层、详情页信息卡。**不要用玻璃铺满列表卡片**，否则可读性和性能都会崩。

**设计 token：**

```css
--glass-bg:        rgba(255, 255, 255, 0.18);
--glass-bg-dark:   rgba(18, 18, 22, 0.36);
--glass-border:    rgba(255, 255, 255, 0.38);
--glass-highlight: rgba(255, 255, 255, 0.55);   /* 顶部 1px 内高光 */
--glass-shadow:    0 12rpx 40rpx rgba(0, 0, 0, 0.16);
--glass-blur:      24rpx;
--glass-radius:    28rpx;
```

**核心实现：**

```css
.glass {
  background: var(--glass-bg);
  -webkit-backdrop-filter: blur(24px) saturate(160%);
  backdrop-filter: blur(24px) saturate(160%);
  border: 1rpx solid var(--glass-border);
  border-radius: var(--glass-radius);
  box-shadow: var(--glass-shadow);
}
```

**高光/折射：** 用 `::after` 画顶部内高光（`inset 0 1rpx 0 var(--glass-highlight)`），用伪元素渐变描边模拟折射边缘；不做真实折射（性能与收益不成正比）。

**背景：** 页面必须有渐变/光斑背景（CSS 动画只动 `transform/opacity`），否则玻璃没有内容可模糊、看起来像半透明白块。

**性能红线：**

- 一屏内 `backdrop-filter` 元素 ≤ 3 个；
- 滚动列表里不放模糊元素（列表项用普通卡片）；
- 动画只允许 `transform/opacity`；
- 图片懒加载 + 固定比例占位，避免布局抖动；
- 首屏图片总量控制在 500KB 内。

**降级：**

- 低端安卓：提供"性能模式"开关（关闭 blur，只保留半透明 + 阴影）；
- 不支持 `backdrop-filter` 的环境：靠半透明背景 + 边框 + 阴影自然降级，不报错；
- 暗色模式：跟随系统，玻璃底色/边框切换暗色 token，文字对比度 ≥ 4.5:1。

**组件清单：** `glass-nav`、`glass-tabbar`、`glass-search`、`glass-card`、`glass-button`、`glass-chip`、`glass-sheet`。

### 11.3 详情页（转化主战场）

1. 顶部玻璃导航（返回/分享）；
2. 预览区：封面 + 多页 swiper（3:4），左右指示点；
3. 信息卡（玻璃）：标题、格式/页数/大小 badge、分类、标签、AI 简介；
4. 免责声明：小字、可折叠；
5. **获取卡（玻璃，视觉最重）**：主链接、提取码、大号"复制链接和提取码"按钮、"如何在电脑上使用"三步图；
6. 收藏/分享按钮；
7. 相关推荐瀑布流；
8. 广告位（二期）。

### 11.4 埋点（一期就要有）

`template_expose`、`template_click`、`copy_link`、`favorite`、`search`；详情页记录来源（首页/分类/搜索/推荐），为二期优化和商业化解耦。
